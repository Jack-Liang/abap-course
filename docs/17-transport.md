> 45分钟 | 阶段：高级篇

## 前置依赖

## 问题引入

你在开发系统写好了程序，怎么把它"搬"到测试系统和生产系统？不能手动复制代码——几十个对象（程序、表、结构、Function……）手动复制不现实。SAP 的"传输请求"机制就是解决这个问题：自动记录变更、打包、传输到目标系统。

## 💡 实战经验

- **一个请求不要太大**：建议一个功能/修复一个请求。把几十个不相关的对象塞进同一个请求，万一某个对象有问题，整个请求都要回退——牵一发动全身
- **本地修改 vs 传输修改**：如果程序是 `$TMP`（本地对象），它不会被包含在传输请求中。只有分配了 Development Class 的对象才能传输
- **传输前检查依赖**：如果你的程序调用了一个自定义 Function Module，传输时必须把 FM 的 Function Group 也一起传——否则目标系统找不到 FM
- **不要直接传到生产**：标准流程是 DEV → QAS → PRD。生产环境的传输需要审批（CTS 或 ITSM），不要绕过审批直接传——这是合规红线
- **Transport Log 是排错利器**：传输失败时，在 STMS 中查看 Transport Log，里面有详细的错误信息（缺少对象、语法错误、激活失败等）
